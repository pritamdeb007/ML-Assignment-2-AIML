# Machine Learning Assignment 2

## Project title
**Phishing Website Classification Using Machine Learning**

## 1. Problem statement
The aim of this project is to compare five supervised classification algorithms for identifying whether a website is phishing or legitimate using the website-characteristic features in the UCI Phishing Websites dataset.

## 2. Dataset description

| Item | Description |
|---|---|
| Dataset name | Phishing Websites |
| Source | [UCI Machine Learning Repository, dataset 327](https://archive.ics.uci.edu/dataset/327/phishing) |
| Problem type | Binary classification |
| Original instances | 11,055 |
| Input features | 30 |
| Target variable | `Result` |
| Target mapping in this ARFF file | `-1` = Phishing; `+1` = Legitimate |
| Missing values | 0 in the uploaded ARFF file (verified by inspection) |
| Exact repeated rows | 5,206 additional occurrences after the first identical row; retained because the file has no unique website identifier proving they are erroneous duplicate websites |
| Preprocessing | ARFF byte values are decoded and converted to numeric values. StandardScaler is fitted within the Logistic Regression, KNN and SVM pipelines using training data only. |
| Train/test split | Approximately 80:20 using 5-fold StratifiedGroupKFold, random seed 42; identical 30-feature profiles are kept in one split only. |
| Full class distribution | Phishing (-1): 4,898; Legitimate (+1): 6,157 |
| Training/test class distribution | Copy the actual output generated by `training.py` in BITS Virtual Lab. |

**Duplicate-handling note:** The ARFF file contains repeated complete rows and repeated feature profiles. The records are retained so that the original 11,055 observations are not silently altered. Since the file does not contain a unique website ID, repeated feature rows cannot automatically be assumed to be erroneous duplicate websites. To reduce train/test leakage, all rows sharing the same combination of the 30 features are assigned to the same side of the split.

## 6. Project files

- `training.py` — loads and checks the ARFF dataset, creates the split, trains and evaluates the five models, and saves the outputs.
- `app.py` — Streamlit interface for test-data upload and model evaluation.
- `requirements.txt` — Python dependencies.
- `test_data.csv` — held-out test rows, including the target column.
- `model/` — five saved model pipelines and `metadata.json`.
- `metrics_summary.csv` — six evaluation metrics for all five models.
- `data/raw/` — original UCI ARFF data file.
- `FEATURE_REFERENCE.md` — plain-language descriptions of the feature names.
